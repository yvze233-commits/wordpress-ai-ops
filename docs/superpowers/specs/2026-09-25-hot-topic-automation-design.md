# 热点驱动 WordPress 自动运营设计

## 目标

让系统围绕“最新时讯”自动运营 WordPress：采集可信热点，生成可选文章标题，按任务配置调用写作 Skill 和审核 Skill，审核通过后自动写入 WordPress，并保留暂停、重试、人工复核和完整审计能力。

默认每天生成 4 篇。默认审核通过后写入 WordPress 草稿；每个任务可以改为 WordPress 待审核或直接发布。

## 用户体验

用户主要配置三类内容：

1. **热点策略**：行业关键词、地区、语言、时间范围、来源优先级和最少可信度。
2. **自动任务**：每天数量、运行时间、写作 Skill、审核 Skill、选题来源、写入方式、是否必须配图和来源链接。
3. **WordPress 站点**：REST 地址、用户名、应用密码，测试连接后作为可用发布站点。

用户不需要理解 RSS XML、JSON 字段路径或 CSS 选择器。系统预设热点聚合来源；高级用户仍可以添加 RSS、JSON 和 HTML 来源，并在保存前测试解析结果。

## 核心流程

```text
热点策略
  -> 采集预设聚合源和启用的备用来源
  -> 规范化标题、URL、摘要、发布时间和来源可信度
  -> URL、事件指纹、标题相似度去重
  -> 过滤时间窗口和已使用/已发布候选
  -> 生成 3 个文章标题候选
  -> 自动选择或人工选择标题
  -> 创建每日内容批次
  -> 写作 AI + 知识库 + 图片库生成文章
  -> 审核 AI 连续两段审核
  -> 通过：写入 WordPress 草稿/待审核/直接发布
  -> 失败：重试或转人工复核
```

## 组件边界

### 1. 热点聚合器

增加一个统一的聚合来源适配器，输出现有 `TopicFeed` 所需的结构：`source_key`、标题、摘要、来源 URL、发布时间、原始数据和可信度。聚合器是默认入口，现有 RSS/JSON/HTML 连接器是备用入口。

聚合器必须：

- 使用明确的请求超时、连接超时和响应大小限制。
- 记录 HTTP 状态、抓取时间、解析错误和最近一次成功时间。
- 只保留最近 72 小时内容，时间窗口可由热点策略调整。
- 为每条候选保存原始来源，不把 AI 生成内容当作事实来源。

### 2. 来源测试和失败可见性

热点来源页面增加“测试来源”动作，先执行一次只读抓取并展示前 5 条解析结果，再允许启用。立即抓取需要显示排队、执行中、成功、失败状态；本地 `sync` 队列直接执行，生产环境由 queue worker 执行。

失败信息至少包含：HTTP 状态、认证/权限错误、超时、响应格式错误、解析配置缺失和最近一次成功时间。失败不会删除历史候选。

### 3. 标题候选生成

对进入选题池且尚未使用的热点调用生成 AI，要求返回 3 个候选标题及其依据：

- 标题必须与原始事件事实一致。
- 不得把预测、评论或推测写成已经发生的事实。
- 候选必须带原始热点引用和发布时间。
- 不能与已发布或已使用标题重复。

自动任务默认按相关度、时效、来源可信度和标题质量选择一个；人工模式可以在批次详情中选择候选标题。

### 4. 自动任务调度

任务每日只生成一个批次，按任务时区和运行时间执行。任务状态为“运行中”时才创建批次；暂停任务不会删除已生成内容，也不会取消已经进入队列的发布任务。

批次创建必须幂等。同一天同一任务只能有一个批次。热点不足时记录 `shortfall`，优先使用可用热点，不足部分按任务配置从标题库补足；标题库也不足时保留短缺状态，不生成无来源文章。

### 5. 内容生成与审核

生成文章继续使用任务快照中的写作 Skill、知识库和图片库。文章必须按任务要求包含图片、图片 alt、来源超链接和配套说明。审核 AI 使用两段审核：事实/证据审核、结构/发布风险审核。任一阶段不通过、证据缺失或图片问题存在时，文章进入人工复核或自动修订上限流程。

### 6. WordPress 写入

审核通过后按任务 `publish_status` 写入：

- `draft`：WordPress 草稿，默认值。
- `pending`：WordPress 待审核。
- `publish`：直接发布，必须由用户在任务配置中主动选择。

发布使用幂等键查找已有文章，重复执行更新原文章而不是创建重复文章。图片先上传媒体库，再替换正文中的图片 URL 和 alt。所有写入保存 WordPress 文章 ID、URL、状态、请求结果和错误信息。

## 状态与审计

热点来源状态：`active`、`fetching`、`error`、`paused`。

候选状态沿用现有选题池状态，并补充标题候选生成记录。每个关键动作写入审计事件：抓取成功/失败、标题候选生成、批次创建、文章生成、审核通过/失败、WordPress 排队、写入成功/失败和无可用站点。

自动发布找不到健康 WordPress 站点时不得静默跳过：文章保留已审核状态，并记录可重试的发布不可用事件。

## 安全与边界

- API 密钥、WordPress 应用密码继续加密保存，页面和 JSON 不回显。
- 抓取只访问用户配置或系统预设的公开来源，不绕过登录、验证码或访问控制。
- HTML 来源使用允许的 CSS 选择器；不执行来源页面脚本。
- WordPress 直接发布是显式任务配置，不作为默认行为。
- 管理后台后续必须增加管理员登录和权限中间件，发布、Skill 和连接配置动作不能匿名开放。

## 验收标准

- 不配置解析路径也能使用系统预设热点源完成一次抓取。
- 来源测试能展示前 5 条标题、时间和链接，并能明确显示失败原因。
- 同一热点重复抓取不会重复进入选题池。
- 每日任务能从热点生成标题候选并创建文章批次。
- 文章经过两段审核后按任务设置写入 WordPress 草稿、待审核或直接发布。
- 暂停任务后不会创建新批次；恢复后可继续执行且同日批次幂等。
- 没有热点时按规则使用标题库或显示短缺，不生成无来源文章。
- 测试覆盖抓取成功、超时、HTTP 错误、解析错误、标题去重、短缺、任务暂停、审核通过和三种 WordPress 写入状态。
